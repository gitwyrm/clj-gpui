# GPUI Kit coverage

clj-gpui 0.1.0 is pinned to **[GPUI Kit 0.6.0](https://crates.io/crates/gpui-kit/0.6.0)** (`gpui-kit` facade → `gpui-pre` 0.3.x + `gpui-component` 0.6 + `gpui-kit-assets`). This document is the inventory of that exact crate, not later git `main`.

0.5.1 names (`ui/text-field`, `ui/divider`) were dropped. Data tables are `ui/data-table`. `ui/table` is Kit's declarative `Table`.

Classification:

| Class | Meaning |
|---|---|
| **A** | Already supported before this coverage work |
| **B** | Straightforward with the current tree + callback architecture; implemented |
| **C** | Supportable, but needs new host state, overlays, delegates, or virtualization |
| **D** | Not appropriate as a `gpui.ui` widget (window/process internals, forbidden surfaces) |
| **E** | Helper / trait / layout primitive rather than a user-facing control |

Coverage-table **status** is not Kit public-API parity by itself:

| Mark | Meaning |
|---|---|
| ✅ | The clj-gpui API in this row is wrapped and usable. Remaining Kit surface, if any, is on a dedicated ⚠️ row or named as out of scope (LSP, `gpui-shell`). |
| ⚠️ | Wrapped, but public Kit APIs listed in this row's notes are still remaining. Do not treat as full public-API parity. |
| ❌ | Not wrapped, or not a `gpui.ui` widget |

`ui/window`, `ui/spacer`, and `ui/hstack` / `ui/vstack` are clj-gpui layout, not 1:1 crate types (`Root`, `h_flex`, `v_flex`).

## Category C — remaining

All intended gpui-kit widget families and all straightforward data-driven public chrome are wrapped. Remaining C work is **arbitrary Rust render/menu closures**: they need declarative host recipes (`{:empty (ui/vstack …)}`, a header node) rather than JSON reproductions of `Fn` / `IntoElement` / `AnyElement`. That leftover surface is Command `child` / arbitrary empty/header/footer / `CommandState::matched_count`, custom Select/Combobox row widgets (`Select::empty` / Combobox `empty` as arbitrary `IntoElement`, `display_title` as `AnyElement`, custom row/section `render`, Combobox `render_trigger` / `footer`), List / DataTable context menus, custom DataTable `render_th` / `render_loading`, arbitrary empty widgets, an arbitrary MessageScroller row renderer (stateful nodes / RootView re-entry), and NavStack `item` as an arbitrary `AnyElement` closure / Window+App inspection (the host recipe is the documented exception; Clojure is not run every frame). Full LSP for the code editor is out of scope; `ui/editor` is the highlighter widget. Kit 0.6 charts are wrapped on `ui/chart` without extra host limits (helpers such as `ui/horizontal-bar-chart` stay). `gpui-shell` and `gpui-wry` are the only intentional subsystem exceptions.

### Overlay family (dialog, popover, menus, sheet, notification)

Kit 0.6 `Root::render` does not paint overlay layers; the host calls `Root::render_dialog_layer`, `Root::render_sheet_layer`, and `Root::render_notification_layer` from `RootView`. Open/close for dialogs and the single crate sheet still goes through `WindowExt` on the next frame so `RootView::render` does not re-enter `Root`. The overlay builder is stored for the overlay's lifetime and runs on every layer paint. It reads a live spec cell (callback ids, title, body, children, footer) instead of capturing the tree from open time — `export-tree` rebuilds the callback registry each render, so a stale `cb-7` would otherwise invoke the wrong function. The builder must not `entity.read` / `update` RootView. Dialog `:on-close` is 0-arg; `:on-ok` / `:on-cancel` are 0-arg. Crate order: OK → `on_ok` then `on_close`; Cancel / Escape / close button / overlay click → `on_cancel` then `on_close`. The host sends `:on-open-change false` from `on_close`. Those ids are captured for the action and sent as **one** callback batch so `:on-ok` cannot `export-tree` and rewire `:on-close`. Each Clojure handler runs at most once per action. Clicking the overlay dismisses the dialog (`:overlay-closable` defaults true even for `:variant :confirm`, which the crate otherwise locks). After a crate-side dismiss the host does not re-open until Clojure’s tree drops `:open?`. Static overlay children use a full path element id (`dialog-key/content/0/1`) so nested stacks cannot collide. Static buttons honor `disabled`, `primary` / `variant`, nested `:custom-variant` (when the overlay builder has `App`), `on-click`, and `text`. Popover is in-tree and controlled (`:open?` + `:on-open-change`). HoverCard is in-tree and hover-driven (not `:open?`); the trigger is any widget; omitted delays keep Kit's 0.6s / 0.3s. Dropdown/context menus use `PopupMenuItem::on_click` (no GPUI Action). Nested `:items` are submenus. Item `:on-click` then menu `:on-change` is one batch. Nested menu `:on-change` sends a path vector so duplicate leaves stay distinct; a flat leaf is still its id. `ui/dropdown-button` is the same menu machinery on Kit `DropdownButton` (action half + caret). `ui/context-menu` is a flex column host (`v_flex` + `min_h_0`), not a block `div`; leftover height is inherited from a `:flex 1` child only when the menu omitted `:flex`, so wrapping a list/table/tree does not collapse the listing. `ui/native-menu` is not in-tree: `:open?` is a show request. On the false→true edge the host materializes Clojure's semantic tree into Kit `NativeMenu` (a presentation snapshot) and then sends `:on-open-change false`. Selecting an item dispatches a host `CljAction` (`slot` + `item_path`) and resolves live Clojure `:on-click` / `:on-change` against the installed tree — never a captured `cb-N`. Nested submenu identities are on the path so duplicate leaf ids stay distinct; parent `:on-change` receives that path as a vector (a flat leaf is still its id). Checked/toggled state stays in Clojure. Kit cannot combine check with disabled: disabled wins over checked when no icon is present. `:disabled` on a submenu wrapper is kept via `From<gpui::Menu>` (Kit's submenu builder cannot); that snapshot drops leaf icons. OS dismiss is not tracked. `ui/command` is in-tree with host-held `CommandState` and the same Action bridge; Kit `on_confirm` is `:on-confirm` (batched with the Action's `:on-change`, not a substitute for it). Parent Command callbacks use the same leaf-id / path-vector contract. `:on-select` is highlight only and is installed only when Clojure provides it. Controlled `:query` / `:selected` run after `Command::render` installs the current model. Native select/query echo latches are bound when that callback batch is actually sent (including a delayed flush after an in-flight callback) and live until the matching callback-seq tree. `ui/status-bar` is in-tree `RenderOnce` (`:left` / `:right` / children); it does not use the Action bridge.

The crate holds **one** sheet. Last open `sheet` in tree order wins. Same live-cell + next-frame open as dialogs. `:placement` is the slide edge. `:footer` is a child node. Notifications are a stack keyed by Clojure id (`Notification::id1`). Presence in the tree means show unless `:open false`. A fingerprint of title|message|variant|autohide|icon|placement skips re-push (re-push would reset autohide). Tree removal dismisses with `suppress_close` so Clojure is not double-notified. Click uses crate `on_click` (fires before delayed dismiss). Autohide defaults **true**. `:placement` is Kit `Anchor`. `:icon` is a kebab name. Sheet `:overlay` is the dimmer; `:resizable` defaults true. Dialog `:ok-text` / `:cancel-text` / named `:ok-variant` / `:cancel-variant` / `:close-button` / `:keyboard` are Kit chrome.

### Delegate collections (list, table, tree, virtual-list)

Clojure sends `{id, label}` (list), `{id, cells}` (data-table; a cell is a string or a supported RenderOnce cell node — progress, tag, badge, avatar, stacks, …), nested `{id, label, items}` (tree), or `{id, label, height?}` (virtual-list, vertical unless `:orientation :horizontal`). Rust owns `ListDelegate` / `TableDelegate` / `TreeState` / `VirtualListView`. Selection callbacks send original Clojure ids. Table column defs travel in `options`, not the description-list `columns` u32. After a column identity or definition change the host calls `TableState::refresh` (rebuilds Kit `col_groups` from `Column::width`, so Clojure `:width` wins). A row-only update remaps cells and `notify`s; a header-group-only update uses `refresh_header_layout`. Both leave a native column resize in `col_groups`. Programmatic table `:selected` uses `set_selected_row` / `set_selected_cell` / `clear_selection` with a suppress flag so `SelectRow` / `SelectCell` do not bounce back as `:on-change`. The host tracks logical Row/Cell/Column mode from those Kit events and the controlled path because Kit `selected_cell()` can stay `Some` after `set_selected_row` (and `selected_row` after `set_selected_cell`); native header sort remaps that logical selection by row id. A cell map without `:cell-selectable` is applied as that row. `render_td` paints a nested cell node with the overlay RenderOnce subset (progress, tag, badge, avatar, stacks, …), not `div().child(text)` only and not input/editor/list/data-table; cell widget ids use `row/id` / `col/id` with length-prefixed wire ids, or `row/index` / `col/index` when an id is missing, rather than visible indices so header-drag reorder keeps retained widget state and a real `"#0"` cannot collide with row 0; `cell_text` / dump export the string or the node's text/value. Tree `:selected` is controlled: the host keeps cloned `TreeItem`s (shared expand `Rc`) and maps ids onto the current visible flattened index. Nested ids apply only while ancestors are expanded. Tree expand/collapse is host-local until the item identity changes (`set_items` would reset it). List `:on-change` is selection; `:on-confirm` is activation (click / Enter). Arrows emit Select only; click and Enter emit Confirm only in 0.5.1, so the host fires `:on-change` then `:on-confirm` on Confirm as one batch against the same callback generation, then one tree. Table left click always emits `SelectRow`; `click_count == 2` then emits `DoubleClickedRow` from that same `on_row_left_click`. Cell mode uses `SelectCell` / `DoubleClickedCell` with the same coalesce. A count-1 click is only `:on-change` (end of the GPUI effect cycle). A count-2 click is `:on-change` then `:on-confirm` (or `:on-double-click`) as one batch so those two never cross callback generations. `:header-groups` is Kit `group_headers`. Pixel `:row-height` is `DataTable::with_size(Size::Size)`; named `:size` is `Sizable`. `:export-generation` plus `:on-export` dumps `TableState::dump` (deferred; `move_column` keeps dump in native header order). Column identity (ids/count/order) is fingerprinted separately from column definitions (label/width/align/selectable) and from rows, so a later row-only or metadata-only tree remaps onto native header-drag order instead of snapping headers back to Clojure. A Clojure column id/order change replaces native columns. Short `:cells` vectors pad to the column count before a move. Searchable lists reapply the active query when Clojure replaces rows. List `:search-placeholder` / `:scrollbar` / `:selectable` / string `:empty` / `:has-more` / `:on-load-more` are Kit List / ListDelegate chrome. DataTable `:stripe` / `:bordered` / `:scrollbar` and TableState sortable/movable/resizable/fixed/loop/row/col-selectable flags are applied each frame. Header sort is in-memory by `cell_text`; `:on-sort` restores the column id; `Default` restores last Clojure row order. `list` / `data-table` / `tree` / `virtual-list` use an outer layout wrapper (same idea as scroll / content-sized widgets): `:size` is square, omitted width fills, default ~200px height unless `:height` / `:size` / `:flex 1`, visual keys live on the wrapper.

Declarative `ui/table` is not this family: Kit `Table` / `TableHeader` / `TableBody` / `TableFooter` / `TableRow` / `TableHead` / `TableCell` / `TableCaption` are `RenderOnce` with no slot, no virtualization, and no selection. The host paints those primitives from nested children so per-cell `col_span`, alignment, and widget children stay accessible. `:accessibility-label` maps to Kit `Table::accessibility_label`. `{:columns :rows :footer :caption}` is Clojure-only shorthand. Layout/style keys use `apply_style` (not `viewport_sized`).

### Chat (message, bubble, attachment, marker, message-scroller)

Kit `Message` / `Bubble` / `Attachment` / `Marker` are `RenderOnce` with no Entity. The wire is Kit primitives (`message-header`, `bubble`, `attachment-title`, …) so Ghost bubbles still go through `MessageContent::bubble` and reaction buttons through `BubbleReactions::action`. Named Clojure keys (`:avatar`, `:header`, `:footer`, `:reactions`, `:overlay`) expand to those children; they must not be confused with sheet `:footer`. Nested style maps cover `Message::with_stack_style`, `AttachmentTitle` / `Marker` `ShimmerStyle`, `Marker::separator_style`, and MessageScroller `with_*_style` / `with_jump_button_renderer`. Chat nodes use the same visual/layout style vocabulary as ordinary clj-gpui widgets. MessageScroller root `Styled` (padding, gap, font/color, bg, border, shadow, align/justify) is applied to the Kit widget; the host wrapper keeps only viewport/box geometry. `MessageScroller` is the class-C host-state piece: one `MessageScrollerState` per `:id`, observed so the jump-to-latest button can appear. Collection diff is leave / remeasure / append / prepend / reset. Row fingerprints ignore generated callback ids; append/prepend also remeasures when a surviving row changed. Stable row `:id` is required for history prepend without `reset` (which re-enables tail follow). Index-only keys make prepend look like append. Scroller rows cannot re-enter `RootView`; they paint the overlay static subset plus this chat family. `:scroll-to-item` / `:scroll-to-end` are Kit `scroll_to_item` / `scroll_to_end` (programmatic; omitted leaves native scroll; `:scroll-generation` re-applies the same target). Remaining: Kit's arbitrary row renderer (`IntoElement` / stateful nodes).

### Product widgets (number, OTP, color, date, editor, dock, sidebar, settings, charts, markdown)

Clojure stays the semantic owner. Rust holds widget `Entity` state only where GPUI requires it. Number-input reuses the input `InputState` slot with a `NumberInput` wrapper; step events parse the current text, apply `:step` / `:min` / `:max`, and `set_value` (which emits `:on-change` as a JSON number). A later input with the same element key clears `as_number` so non-numeric text still emits a string; the step subscription stays on the entity but no-ops while `as_number` is false. OTP `:on-change` is crate-complete-only; incomplete typing is not overwritten while focused. Color is hex or JSON `null`. Kit `ColorPickerState::set_value` takes only `Hsla`; a controlled `Some` → `nil` recreates the state entity (starts empty, no `:on-change`). Date is ISO; `set_date` is skipped when the value is unchanged so an open picker is not closed every frame. Editor is highlighter-only (`EditorState` + `set_highlighter` on language change). Undo/redo groups and fast typing emit several crate `Change` events; the host defers one `:on-change` with the latest string and will not send another until the next tree assigns a fresh `cb-N` (export-tree is monotonic, so a second send of the same id is `unknown callback`). Charts fill an outer `viewport_sized` wrapper (same layout/style keys as list/table). RootView uses `chart_viewport()` for that default height, matching the Dock path, so omitted `:height` on horizontal bars is `n * 28 + 40` (at least 180). `ui/chart` kinds are Kit `LineChart` / `BarChart` / `AreaChart` / `PieChart` / `RadarChart` / `CandlestickChart` / `SankeyChart`. Convenience helpers may simplify Kit; they must not hide it. Bar `:alignment` is Kit `BarAlignment` (`:left` / `:right` horizontal). `:tick-margin 0` is clamped to 1. Partial Sankey node `:color` keeps Kit's `chart_1`…`chart_5` cycle for the other nodes. Line charts follow Kit (no forced `.dot()`, tooltip `.id`/`.name`, stroke style, x-axis, grid). Area charts accept multiple `:values` series. Pie charts omit Clojure `:outer-radius` unless set; the host forwards Kit's height×0.4 layout default into `.outer_radius()` because Kit's paint path does not apply that fallback. `:inner-radius` is a donut. Resizable slots use `used_resizables` + `retain` like other dynamic entities. Notification fingerprint ignores callback ids so an unchanged toast is not re-pushed; click reads the current `cb-N` from the slot at click time. Dock `CljPanel::panel_name` is always `"clj-gpui-panel"`; panel paint does not re-enter `RootView` (static overlay painter + markdown/chart). Settings fields are rebuilt each `RootView` frame (`Settings` is `RenderOnce`). A `:variant :dropdown` / `:select` field with option `:items` is a field, not a group. `NavStack` is a host slot (`used_nav_stacks` + `retain`): Clojure's `:stack` is the trail; each history entry is its own `CljNavPage` entity; a parallel forward branch retains popped entities so `forward()` restores them; live cells update and `notify()` every frame (active and forward) so callback ids stay current. An unknown controlled page id leaves the native stack unchanged. `Command` is a host slot (`used_commands` + `retain`) with Clojure-owned entries. `StatusBar` is `RenderOnce` (no slot).

## Path to near-complete coverage

Clojure stays the semantic owner. Rust holds widget `Entity` state only where GPUI requires it. The slot map now covers input, textarea, slider, select (flat or `SelectGroup`), combobox (flat or `SelectGroup`), list, data-table, tree, OTP, color, date, editor, virtual-list, message-scroller, nav-stack, dock, resizable, and command (`CommandState` plus the `CljAction` slot+`item_path` bridge shared with NativeMenu). Overlay sync covers dialog, alert-dialog, sheet, notification, and NativeMenu show-on-rising-edge; popover/hover-card/menus/status-bar are in-tree. Remaining C work is Command `child` / arbitrary empty/header/footer / `CommandState::matched_count` / custom Select/Combobox rendering (`render_trigger`, `footer`, arbitrary empty/`display_title`) / List and DataTable context menus / custom DataTable `render_th` / `render_loading` / arbitrary empty widgets / an arbitrary MessageScroller row renderer / NavStack `item` as an arbitrary `AnyElement` closure (the host-evaluated recipe is the documented exception) — not a new architecture. `gpui-shell` and `gpui-wry` are the only intentional subsystem exceptions.

| `command` | `:on-cancel` | none (0-arg; empty-query Escape) |
| `list` | `:on-confirm` | original Clojure row id (click / Enter; same batch as `:on-change`) |
| `data-table` | `:on-confirm` / `:on-double-click` | original Clojure row id, or `{:row … :col …}` in cell mode (double-click; same batch as that click's `:on-change`) |
| `data-table` | `:on-export` | `{:headers […] :rows [[…]]}` from Kit `TableState::dump` (not option-id restored) |
| `data-table` | `:on-sort` | `{:id column-id :sort asc/desc/default}` (column id restored) |
| `list` / `data-table` | `:on-load-more` | none (0-arg). Host latches only after a callback is sent, until rows / `:has-more` / `:loading` change or `:on-load-more` appears (`nil` → present). A regenerated present callback id does not reset the latch |
| `dialog` / `alert-dialog` | `:on-close` / `:on-ok` / `:on-cancel` | none (0-arg) |
| `dialog` / `alert-dialog` / `popover` / `hover-card` / `sheet` / `native-menu` | `:on-open-change` | boolean. NativeMenu is `false` after a rising-edge show (the OS menu remaining visible is not tracked) |
| `sheet` / `notification` | `:on-close` | none (0-arg) |
| `number-input` | `:on-change` | number |
| `rating` | `:on-change` | integer `0..=:max` |
| `stepper` | `:on-change` | original Clojure item id |
| `pagination` | `:on-change` | 1-based page number |
| `otp-input` | `:on-change` | string, only when every cell is filled |
| `color-picker` | `:on-change` | hex string or `nil` |
| `date-picker` | `:on-change` | ISO string, `[start end]`, or `nil` |
| `editor` | `:on-change` / `:on-blur` | string |
| `virtual-list` / `sidebar` | `:on-change` | original Clojure row id |
| `settings` | `:on-change` | `{:id original-field-id :value …}` |
| `resizable` | `:on-change` | vector of px sizes |
| `nav-stack` | `:on-forward-change` | vector of original page ids, Kit `forward_views()` order (nearest first). Empty after first mount is not sent |

The wire still uses JSON strings. `gpui.ui` keeps a map of wire id → original Clojure id and restores it in the callback. `{:id :dark}` yields `:dark`; `{:id "custom-id"}` yields `"custom-id"`. If two options share a wire id (`:dark` and `"dark"`), the first wins.
